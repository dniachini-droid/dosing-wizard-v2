# ALK V2 — RULE TRACEABILITY

Exhaustive inventory of the normative rules of the frozen canon, with an
authoritative implementation owner for each.

**Authority:** `docs/canon/REEF-CHEMISTRY-ENGINE-V2-CANON.md` under `SHARED_V2_FREEZE_2`
and `ALK_V2_FREEZE_5`. Nothing here amends the canon.

## Column meanings

| Column | Meaning |
|---|---|
| **Rule** | The stable rule ID where one exists; otherwise the canonical section identifier used as a stable handle in this package. |
| **Canon** | Canonical source section. `MR` = Master Rule, `PI` = Part I, `PII` = Part II, `ALK-nnn` = Part III section, `M-n` = capability contract, `IX`/`X` = Parts IX/X. |
| **Owner** | The single authoritative implementation owner. One owner per rule — `INV-I2`. |
| **Inputs → Output** | What the rule consumes and produces. |
| **Equation / condition** | The deterministic formula or decision condition, where the rule has one. |
| **Reason codes** | Codes the owning module may emit for this rule (`ALK-V2-REASON-CODES.md`). |
| **Fixtures** | Fixtures exercising the rule (`fixtures/`). |
| **Boundaries** | Boundary cases, exclusions and prohibitions that a naive implementation would get wrong. |
| **Dependencies** | Rules or capabilities this rule consumes or is constrained by. |
| **Active** | Whether the rule is behaviourally active during the Alk-only V2 runtime. `ACTIVE` — runs. `GATED` — capability-gated, default off. `BLOCKED` — an open issue prevents the dependent output; the rule emits a refusal. No row carries this state after `ALK_V2_FREEZE_5`. `NOT_RUN` — the rule's inputs do not exist for alkalinity. |
| **Finding** | `NO_PROBLEM`, `IMPLEMENTATION_DETAIL_ALREADY_DETERMINED`, `CANON_DEFECT`, `OWNER_DECISION_REQUIRED`, optionally suffixed `(RESOLVED F5-nn)` where an `ALK_V2_FREEZE_5` owner decision determined it — full analysis in `ALK-V2-OPEN-ISSUES.md`. |

## Owner vocabulary

`VALIDATION` · `SEGMENTATION` · `TREND` · `UNCERTAINTY` · `SUPPORT` · `CONSUMPTION` ·
`POTENCY` · `RESPONSE` · `MAINTENANCE` · `RETURN` · `SAFETY` · `RETEST` · `CAPABILITY` ·
`OUTPUT` · `AUDIT` · `PRESENTATION`

These map one-to-one onto the modules in `ALK-V2-MODULE-DESIGN.md` §4, so single-ownership
is mechanically checkable.

A machine-readable copy of this table, with the same field set, is
`traceability/alk-v2-traceability.json`.
