Turn it on

Turning it on adds a collapsed block to the bottom of the screens that have one. It never changes a sentence, a number or a recommendation anywhere else.

Why they are separated at all

A reason code is a contract between the engine and whatever renders it. It is precise, it is stable, and it is testable — which is exactly why it is useless to a reef keeper. It names the rule that fired, not the thing that is true about their tank.

The sentence a keeper reads and the code an engineer reads are two different jobs. Putting them in one string does neither well: the code makes the sentence clinical, and the sentence makes the code ambiguous.

The check is a check, not a promise. check-plain-english.py fails the build if a reason code, a canon marker or an internal variable name appears anywhere outside a block like this one.
