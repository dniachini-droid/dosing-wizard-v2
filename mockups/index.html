Dosing Wizard V2

Build one — screen mockups

Eleven screens with hand-written sample data. No engine, no storage, no framework — plain HTML and CSS, so the interface can be judged before anything is implemented, and so the implementation has something to aim at.

Sample tank throughout: a 77-litre mixed reef, alkalinity around 8.7 dKH, target range 8.6–9.2 dKH, dosing about 9 mL/day of a 100 g/L sodium carbonate solution through a pump that steps in 0.1 mL/day. Every reason code and every payload number is real: the codes come from the catalogue and the numbers follow from the sample data.

Behind the screens

Three things these are built to prove

1 · Refusing is normal. The frozen specification has twenty-four recorded defects and eight open owner decisions. Most real assessments will decline part of the answer. Every refusal here is a designed output: it names what is missing, what would fix it, and what is still known. None of them is a blank.

2 · Notices are a list, not a strip. Reason codes add up. A realistic assessment emits somewhere between eight and twenty-five, graded from explanatory to safety, each carrying mandatory numbers. Every screen shows them as an expandable list, ordered by severity, with the payloads visible.

3 · Status is six things, not one. Position, trajectory, evidence, intervention phase, response and overshoot are independent. A change can be going exactly as predicted and have overshot at the same time. One badge would drop whichever mattered, so there is no single badge anywhere in these screens.

Eleven things the screens could not express

Places where building the interface and reading the specification disagreed. Each one is a real question for the owner rather than something to be decided by whoever draws the screen. They are listed in full, with what breaks and what the options are, in CONTRACT-GAPS.md, and each is flagged in a dashed box on the screen where it shows up.

Nothing in these mockups resolves any of them. Where a screen had to show something, it shows the honest version and says what is missing.
